# obsidian-logoxide

The Logoxide plugin for Obsidian: finds, searches, links, and autocompletes Bible references in the vault. User-facing overview: `README.md`; design: `doc/plan.md`. It was topos's `obsidian/` folder until October 2026 (history kept with `git subtree split`).

## Where things live

- **topos** (`~/Development/rust/topos`, GitHub `MasterTemple/topos-bible`) finds and parses references, and nothing else; it must stay usable without this plugin. Bible *text* belongs here (or in what this plugin depends on), never in topos-bible itself. Changes the plugin needs in the bindings or the library go into topos (tell the user; don't push or publish topos unless asked).
- The plugin depends on logoxide's WebAssembly package (`~/Development/rust/logoxide`, its `crates/logoxide-ffi`), which re-exports topos's whole API, so imports are `from "logoxide"`: `"logoxide": "file:../../rust/logoxide/crates/logoxide-ffi/dist/wasm/pkg"`. Rebuild it after changing logoxide's or topos's bindings: `(cd ../../rust/logoxide/crates/logoxide-ffi && npm run pack:wasm)`. The worker gets the same WebAssembly from the plugin. Changes the plugin needs in packages, installing, or caching go into logoxide (same rule: tell the user, don't push or publish).
- Tests read topos's shared completion cases (`crates/topos-lib/tests/cases/complete.txt`) and run its CLI (`target/debug/topos`, `cargo build -p topos-bible-cli`); `test/topos.ts` finds them (`$TOPOS_DIR`, `$TOPOS_CLI`).
- **file-plus-plus** (`../obsidian-plus-plus/file-plus-plus`, `"file-plus-plus": "file:…"`, read its CLAUDE.md) is the plugin's base class: `ToposPlugin extends FilePlusPlusPlugin`, with USX files as its format (`src/bible/`). It owns `onload` (the plugin's setup is in `onLoaded`), `data.json` (topos's settings are merged into `FppSettings` through `defaultSettings`; migrations run in `loadSettings`), and the settings tab (topos's settings are `ToposSettingsPanel`, shown first through `displaySettings`). Its `saveSettings` runs on every scroll (positions), so topos's settings save with `saveToposSettings`, which also redraws references. Plugin members must not collide with its (`index`, `copy`, `documents`, `deviceId` are taken: the reference index is `refs`). Its classes are prefixed `tpb` in the build (`esbuild.config.mjs` uses its `rewritePrefix`); refer to them through `PREFIX`.
- EPUB++ is next to it, in `~/Development/typescript/obsidian-plus-plus/`.

## Commands

- `npm install`, `npm run build` (typecheck + esbuild to `dist/`: `main.js`, `styles.css` with file-plus-plus's first, `manifest.json`), `npm run dev`, `npm test` (`node --test`), `npm run typecheck`.
- `scripts/install.sh ~/Obsidian`: builds and copies `dist/` into the user's vault (`.obsidian/plugins/logoxide/`). Do this after each commit.
- Headless Obsidian (never the user's): `FPP_CDP_PORT=9341 ../obsidian-plus-plus/file-plus-plus/scripts/obsidian-headless.sh desktop|mobile|stop` from this folder opens `test-vault/` (its plugin folder links to `dist/`; put a Bible in `test-vault/Bibles/BSB/`, which git ignores, e.g. the BSB's USX from gracious-tech/fetch_collection; logoxide packages go in `test-vault/Logoxide/`, also ignored: `cd test-vault/Logoxide && LOGOXIDE_HOME=$PWD lx init && lx add --git file://$HOME/Development/logoxide-packages/kjv`). Drive it with that folder's `cdp.ts --eval` / `cdp-input.ts --click|--tap|--hover`. `Links.md` there has every reference syntax, `Highlights.md` partial-verse highlights with a comment, `Media/Sermon.srt` references in a transcript. To test with EPUB++ and Transcript++ too, symlink their builds into `test-vault/.obsidian/plugins/` (`epub-plus-plus` → `…/epub-plus-plus/packages/obsidian/dist`, `transcript-plus-plus` → `…/transcript-plus-plus/dist`; `community-plugins.json` lists them) and write an EPUB with `test/epub.ts` into `test-vault/Books/` (ignored). A Bible with a recording: `node test/audio.ts test-vault/Logoxide/imports/audiotest <serve dir> http://127.0.0.1:8766` (John 1:1-5 and 3:16-18 read by espeak-ng, WebVTT timings, listed with `lx media add`; the package needs `timings = "timings/"` under `[media]`, which `lx media add` doesn't write, else `timings()` is empty), serve it with `python -m http.server 8766` in the serve folder, and add `audiotest = { path = "imports/audiotest" }` to `test-vault/Logoxide/logoxide.toml` (then `lx install --project . --library ../.logoxide` there). When another session has the headless instance, use a copy of the vault: `FPP_VAULT=<copy> FPP_OBSIDIAN_PROFILE=<dir> FPP_CDP_PORT=<other port>`, with real files (not the `dist/` link) in its plugin folder.
- Use `rg` and `fd`, not `grep` and `find`.

## Layout

- `src/core/`: no Obsidian imports (filters, the index wrapper, sorting, completions, link templates, settings data), tested directly with Node.
- `src/indexers/`: the Web Worker (`worker.ts`, bundled separately and embedded in `main.js` by `esbuild.config.mjs`), the CLI runner, `vault.ts` (the reference index on disk).
- `src/core/syntax.ts`: how references are written in notes (`[text](John 1:1)` links, `[John 1:1]` explicit links, `![John 1:1]` embeds, bare references), `wholeReference` (the target must be all reference), shared by the editor and reading view. `src/core/verse-locator.ts`: `v=3:16-18` locators. `src/core/bibles.ts`: folders of USX files as Bibles. `src/core/translations.ts`: the translations a reference can name (`John 3:16 KJV`): the Bibles' folder names plus the settings' names and aliases, built into topos's `ToposTranslations` (`plugin.translations()`, rebuilt when Bibles, settings, or verse counts change); `findReferences` and completion take them, and a reference's `translation` picks the Bible for links, hover, and embeds (`bibles.named`/`forText`).
- `src/bible/`: the file-plus-plus format (`format.ts`, reading `ToposBook` from topos's bindings), its reader (`reader.ts`: a section per chapter, verse markers are `span.topos-verse`; every USX marker is a `data-style` from topos-bible-markup, styled by `USX_CSS` in the `document` layer, see `doc/usx-styles.md` for which markers matter and what's still wrong; a preview renders only its passage), the vault's Bible stylesheet (`styles.ts`, the `bibleCss` setting: one constructed sheet per window, adopted by each reader's shadow root after its own styles, replaced when the file or the Display tab's settings change; those come first, as `src/core/display.ts`'s `displayCss` in the `document` layer: verse numbers and their color, red letters, and hiding footnotes or cross references, which `bookTextOptions` renders when either shows; headings and notes change the HTML, so open Bible tabs render again, `rerenderBibles`), embeds and hover previews (`embed.ts`; a play button when the passage's Bible has a recording of it, which plays it in the embed), `BibleLibrary` (`library.ts`), `VerseCounts` (`counts.ts`: each book's verse counts from `ToposBook.usxChapterVerses`, read in the background into `verse-counts.json` in the plugin's folder), `LogoxideBibles` (`packages.ts`: the Bibles the vault's `logoxide.toml` asks for, at its root else in the library's folder, as `logoxide.lock` pins them, read from the library (the `logoxideLibrary` setting, `.logoxide/` by default: hidden and not synced, so each device installs what the lock pins, `BibleManager.installLocked`, once per lock text; read through the adapter) or a path package's folder. The packages folder (`logoxideBooks`, `Logoxide/` by default, the old library setting's value when upgrading; `moveOldLibrary` moves its `packages/` into the library) holds `logoxide.toml`, the lock, `imports/`, stubs, and EPUB copies: vault files, so the reader, hover, embeds, and EPUB++ open them. `hideLogoxideBooks` hides it (a style rule in the explorer, and an entry in Obsidian's `userIgnoreFilters`, remembered as `hiddenFilter` to take out again). `project.packages()` lists what collections bring in (`dependencyOf`); a collection's Bibles and books are the vault's, another package's dependencies aren't. A package turned off (`enabled = false` in `logoxide.toml`; `LockedEntry.enabled`, also false for what an off collection brings in) is listed in `installed` (named from its `logoxide.toml` alone, `Logoxide.packageInfo`) but not opened, so its Bible, books, stubs, and EPUB copies leave the vault until it's on (`BibleManager.setEnabled`, the Library tab's toggle and All/On/Off chips; `isEnabled`, `enabledPackages`, `disabledPackages`). Book packages' EPUBs are copied to `Logoxide/<package>/<path>` (`syncCopies`; written again when they differ; only copies recorded in the plugin's `logoxide-copies.json` are removed) and are always searched for references (`isBookCopy`); cache in the plugin's `logoxide-cache/`; `BibleLibrary` lists them as Bibles named by their abbreviation (`package: true`, counts from logoxide rather than `VerseCounts`) and leaves the packages' files out of its folder Bibles (`isPackageFile`). Each book opens through a **stub** (`src/core/stubs.ts`): `Logoxide/<dependency>/<title>.bible` (`stubNames`: the book's title from logoxide, `fileName`-safe, made unique with the file's name; no title: its path), renamed (`rename`: links and the annotation files beside it follow, with Obsidian's update-links setting on for the move) when its name changes; EPUB copies are named by title too (their record keeps each copy's package file), a line of JSON naming the package (as `logoxide.toml` does) and the book's path in it, never the version. The Bible format takes `.bible` too (`loadBook` reads the library's file through `stubTarget`; a file of several books, a whole Bible in OSIS or ThML, has a stub per book naming it, `"book": "JHN"`, and such books and other formats than USX and USFM come from logoxide, `stubBook`); `files()` gives stubs, so the reader, hover, embeds, links, and annotation files (beside the stub) all use the stub's path, which updates never move. `syncStubs` writes them after each load and deletes only stubs no package has (never other files). A link made in a package's book records its edition (`v=3:16&ver=1.0.2&vh=…`: `withEdition`/`splitEdition` in `core/verse-locator.ts`; the version and 8 hex digits of the verse's hash, from `LogoxideBibles.edition`, which `loadBook` puts in `BibleBook.edition`); `BibleReader.followed` finds the words again by that hash when the installed version has others at that number (renumbered: it goes there and says so; reworded: it says so). `toggleSource` on a stub shows the package's file read-only, and back. Packages whose own files changed (`changedPackages`) get a notice, a *Restore* button in the settings, and the `restore-logoxide-packages` command (`BibleManager.restore`, the installer's `Repair` mode; local `file://` repositories need `lx install --repair`). Searching skips packages' files but not the notes beside stubs), `BibleManager` (`manage.ts`: adding, installing, and removing packages through logoxide's `LogoxideInstaller`, downloads with `requestUrl`, files with the adapter; catalogs (the manifest's `[settings] catalogs`, else eBible.org's, fetch.bible's, CCEL's, and CrossWire's lists; read as bytes, `parseCatalogBytes`, since a SWORD repository's is a `.tar.gz`) kept a day in the plugin's `catalogs/`; registries (`[settings.registries]`, searched before the catalogs; `addRegistry`, `removeRegistry`, the *Registries* settings): a `Registry` entry is added as `{ registry: catalog, version }` (`addRelease`), and `Download` requests are answered with `requestUrl` or a vault file (a path outside the vault is refused: lx); eBible.org, fetch.bible, CCEL, and SWORD imports (fetch.bible's books downloaded eight at a time; a SWORD module's zip from the first of its `zipUrls` that answers) go in `imports/<id>/` beside the manifest as path packages; `updateImports` makes each again, like `lx import --update`, through `findUpstream`, `importIsCurrent`, and `updateImport`: the *Update imports* setting, Check and Update, and the `update-logoxide-imports` command), `add.ts` (how catalog entries are described: kind, license, language, source). Book files are USX or USFM (`BOOK_EXTENSIONS`; USFM is read as USX through logoxide's `usfmToUsx`), `parallel.ts` (the commands that open a book in another Bible, beside it kept on the same verse through the readers' `relocated` events), and recordings (a package's `[media]`, with WebVTT timings: `LogoxideBibles.recording(stub, bookId)` gives the book's file and each verse's `Timing`, `recorded(bookId)` the Bibles that may have one, synchronously for menus): `view.ts` (`BibleView`, the plugin's `createView`: a *Listen* toolbar button, file-plus-plus's `MediaPlayer` above the text under a line naming the verse being read; `followVerses` marks that verse with the reader's `setPlayingRange` and file-plus-plus's `PlaybackFollower` keeps it in view while `followPlayback`; verse numbers (while it plays, or with Ctrl/Cmd), `Play from 3:16`/`Play 3:16-18` in the selection menu (a right-click without a selection: the verse under the pointer, `verseAtPoint`), `onNavigate`/`goToToc` while playing move playback; `whenRecording()` for `ToposPlugin.playPassage`, the editor menu's *Play John 3:16 (AUD)*), `media.ts` (`BibleMedia`: downloads a recording with `requestUrl` when first played, after a dialog giving its size, checks it with logoxide's `verifyMedia`, keeps it at `<library>/<mediaStorePath>` (`.logoxide/media/bd/bdc6…`, no extension: it plays from `adapter.getResourcePath`), one download per hash at a time; `downloaded`/`clear` for the settings), and `src/core/timings.ts` (`timingAt`, `timingOf`, `clipOf`, `formatSize`).
- `src/documents/`: Bible references in other file-plus-plus plugins' documents: `provider.ts` (the annotation provider shared by EPUBs and the rest: look, menus, hover `preview` into the Bible), `support.ts` (`DocumentSupport`: every file-plus-plus API through `file-plus-plus:api-ready`, searching `extractText`; EPUB++ is left to `src/epub/`, which uses the index and CFIs).
- `src/settings.ts`: the settings, in tabs (Bibles, Display, Library, Add Bibles, References, Search, and file-plus-plus's own settings, which `adoptFilePlusPlus` moves into Reader and Highlights by their headings after it draws them). Laid out like Obsidian's own tabs: `section()` makes a `setting-group` card per heading; `filteredList` puts a filter field at a card's top; descriptions go through `md()` (`code` in backticks, *names* in asterisks). A tab redraws itself (`redraw`), not the whole page. `src/settings/browse.ts`: the catalog browser (search, kind and source filters, a row per package with an Add button; its state survives redraws), the git URL row. `openSettings(plugin, tab)` opens a tab (the `add-bibles` command).
- `src/editor/`: CodeMirror decorations (live preview hides link syntax, `![…]` is a widget; `Prec.highest` and an inclusive replace keep Obsidian's own link widgets out) and autocomplete. Link clicks in editors are caught in the capture phase (`interceptLinkClicks`): Obsidian's live preview reads `[text](John 3:16)` as a link to a note `John` and would create it. `openLinkText` is patched for Obsidian's own links to references (`[x](John.3.16)`). `src/reading.ts`: reading view. `src/view/`: verse search, one React app (`PaneApp`) in the search tab (`SearchPane`) and the sidebar (`SearchView`, on `plugin.search`, narrow: filters and display options fold away; `viewHost` builds both views' `PaneHost`; file type chips from `topos`'s `ToposIndex.extensionCounts`, paths and globs/regexes (`src/core/paths.ts`, `Where`) through `ToposPaths`/`queryPaths`, which every query uses, results rendered as Markdown; Obsidian calls go through its `PaneHost` so it renders in tests), sharing `parts.tsx`; `src/suggestions.ts`: how the editor's autocomplete and the dialogs render suggestions (verses show their text, from `BibleLibrary.text`); `src/epub/`: EPUB++ integration.
- `test/plugin.test.ts` loads the built `dist/main.js` against a stand-in for Obsidian's API (with happy-dom for file-plus-plus); `test/obsidian-stub.ts` stands in for Obsidian's runtime in bundled editor tests. `test/media.test.ts` bundles `src/bible/media.ts` with its own stand-in (dialogs answered, `requestUrl` from a table) and real logoxide. Modules tested with plain `node --test` must not import file-plus-plus or `obsidian` (they aren't loadable there).

## Conventions

- Reference logic (parsing, completion, search rules) lives in topos, not here. The plugin only adds presentation and Obsidian glue.
- Offsets are UTF-16 (`OffsetUnit.Utf16`) everywhere.
- Bible text comes from the vault (USX now; SWORD modules later through a sword-modules FFI that hands each entry's markup to `ToposBook`/topos-bible-markup), never from topos itself.
- `tsconfig.json` has no `erasableSyntaxOnly`, since file-plus-plus's sources use parameter properties; code that `node --test` runs directly must still use only erasable syntax.
- Mobile matters as much as desktop. Never test in the user's running Obsidian.
- The user may have uncommitted edits here; don't commit over them without asking.
- Commit messages end with a `Co-Authored-By` line.
